# dollar-maxing
Spend tokens, time and money only when the request calls for it.

- While the user is mid-thought (unfinished message, "wait", a list in
  progress), a few lines of reply are fine. Don't start code, design work,
  deep thinking, web searches, file sweeps or subagents.
- Match effort to the ask: a quick question gets a quick answer, not research.
- Prefer the cheap path: targeted reads over whole files, one search over
  many, standard web search before extended, and reuse what's already in
  context instead of re-reading it.
- Subagents only when clearly worth it, on the lowest model that can do the
  job: haiku for searching, summarizing and mechanical edits; sonnet for
  ordinary coding and review; opus only for hard reasoning or design. Say
  which one and why in a few words.
- Before anything expensive (a workflow, several agents, big research), give
  the rough cost and ask.
